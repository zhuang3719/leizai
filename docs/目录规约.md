# 雷仔目录规约（权威 · v1 · 2026-09-13）

> 本文件是雷仔文件系统的**唯一权威规约**。主我与所有雷影（程序员/美工/文案）一律遵守。
> 规约的核心：**每个文件都有唯一、明确的落点；运行依赖绝不乱动；废弃只归档不删除。**

---

| 目录/文件 | 用途 | 归属 | 可动性 |

| `雷影/{程序员,美工,文案}/` | 三实例，结构镜像主引擎 | 主我统筹 | 🟡重启/同步归主我 |

## 二、文件落点规则（主我 + 全体雷影）

| 产物类型 | 落点 |
|---|---|
| 非文本产物（图/视频/音频/代码包/数据） | `<REPO_ROOT>\项目文件\<会话id>\<图片\|视频\|音频\|代码\|其他数据>\` |
| 文本：进度/方案/报告 | `workspace\projects\<会话id>\`（由 log_progress 维护） |
| 设计文档/规约 | `docs\` |
| 临时脚本/一次性产出 | 用完即删；确需留则 `scripts\_archive\` |
| 备份文件 | 同目录 `_archive\`，或就地 `<原文件>.bak_<用途>_<YYYYMMDD_HHMM>` |

---

## 三、命名规范
- **备份**：`<原文件名>.bak_<用途>_<YYYYMMDD_HHMM>`（如 `mailbox.js.bak_redeliver_20260913_165242`）
- **归档目录**：一律 `_archive/`（就地或根级）；历史批次目录用 `_历史<主题>_<日期>/`
- **会话项目**：`s-<id>`（与引擎会话 id 一致）
- **临时**：`_` 前缀，且**用完即清**

---

## 四、执行保障（"不出错"四道保险）
1. **引用审计先行**：移动任何文件前，grep 全仓库（`src/`+`scripts/`+`*.cmd`+`*.ps1`+`package.json`+`config.json`）确认无引用；有引用则跳过。
2. **只归档不删除**：一律 `move` 到 `_archive/`，绝不 `delete`。
3. **每步验证**：四实例 `/api/sessions` 全 200 + 红线文件在位。
4. **红线逐条对照**：第一节 🔴 项，绝不移动。

---

## 五、变更流程
- 改引擎(`src/`)/客户端(`app/`,`shell/`) → **派雷影**（程序员），主我复验。
- 同步代码到雷影 `src/` → **主我**（雷影不能同步自己）。
- 移动运行文件（exe/dll/启动脚本）→ **默认不做**（破坏 .NET 同目录加载 + 脚本引用，风险高收益低）。
- 目录结构大改 → 先出方案、经主人确认，再分阶段执行。
